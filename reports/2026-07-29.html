Sol 的各位用户，大家好！我已重置所有 ChatGPT Work 和 Codex 用户的使用限额。与此同时，快速同步一下 GPT-5.6 Sol 使用限额的最新情况。

过去几周，很多用户告诉我们，Sol 消耗 Codex 限额的速度比预期更快。需要说明的是，我们并没有削减任何订阅计划的用量。

我们一直在深入调查原因，并已落地多项改进。因此，我们预计你们的限额在 Sol 的典型使用下将延长约 18%。部分用户从今天起应该会看到显著更大的改善。明天，我们还将恢复调查期间临时暂停的五小时限额。

以下是我们的发现：
- GPT-5.6 Sol 更愿意长时间工作、发起额外的工具调用，并跨工具和子代理协调复杂的工作流。这让它更擅长解决难题，但某些任务的消耗远超我们的预期。
- 在相同的推理力度下，Sol 也比以往的模型更卖力。Sol 的 High 档位消耗的 token 可能比 GPT-5.5 的 High 更多。
- 程序化工具调用（也称为 code mode）让 Sol 能更灵活地并行运行工具调用，或在等待时继续工作。但这也导致每轮产生更多回复、更多缓存的输入 token，用量超出预期。
- 当 Sol 等待工具调用完成或执行大量网页搜索时，这一点尤为明显。我们已改进了对这两种情况的处理，并将继续提升 code mode 的效率。
- 影响也非常不均衡。中位数用户其实觉得 Sol 的 token 效率相当高，但一些处理更难任务的重度用户发现用量消耗快得多。发布前我们过于关注平均和中位用量，忽略了一些长尾情况会消耗明显更多的用量。

Sol 是 Codex 能力上的一次重大飞跃，但能力与效率并不总是同步提升，有些问题只有在真实规模下被大量使用时才会显现。我们本应更早意识到这一点，并更坦诚地与大家沟通。

你们继续开拓前沿，我们会持续提升效率，并在过程中不断同步最新进展。
💡OpenAI 罕见定量披露智能体模型的 token 经济学：GPT-5.6 Sol 因更长工作时间、更多工具调用和 code mode 并行，消耗超预期，优化后限额仅延长约 18%，中位用户无感但重度长尾用户被烧穿；信号明确——智能体能力提升与 token 成本爆炸并存，配额/定价设计是 agentic 产品的核心 PM 难题，均值指标会掩盖长尾灾难。
