问：律所界相当于 Bun 重写的是什么？
Nicolas Bustamante @nicbstme
我记得在我的前公司 Doctrine，我们把前端从 AngularJS 1.7 重写到了 React。那是个大工程，也是个重大决定。花了大约六个月，还有一整支才华横溢的软件工程师团队。

这就是为什么 Bun 的重写让我觉得特别有意思。Bun 原本是约 535k 行 Zig 代码。重写产出了超过 1M 行的 Rust diff！但是……只花了 11 天。

高峰期他们并行运行了大约 64 个 agent，分布在 4 个 worktree 中，每个 workflow 有 16 个 agent。总共生成了 6,500+ 个 commit（哇！）

工作量也很大，因为他们不是简单地来一句"plz Code go from Zig to Rust"，而是制定了移植指南、错误分析流程，还配了专门的对抗性 agent 来审查 diff、找出错误等等。人类的工作不是写代码，而是设计和监督整个过程，也就是所谓的"管理 agent"。

在我看来这是件大事。世界上有太多重要的软件被困在旧框架、旧语言、旧架构和旧安全模型里，因为重写太贵、风险太高。

如果这套方法论变得可靠，我们就能快得多地把软件迁移到更安全的语言、更好的运行时、更干净的架构和更安全的默认配置上。

太多软件还在跑老旧的 COBOL，而很快迁移到 Rust 将变得轻而易举。
