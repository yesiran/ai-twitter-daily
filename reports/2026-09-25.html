我认为，无论你转向哪个抽象层级，软件工程的“难度”基本都保持不变，因为人的认知会适应新工具，直到再次充分发挥自身能力。

工具只是让某些行动成为可能，并不是能让工作凭空消失的魔法棒。

过去，做好软件工程极具挑战。现在，尽管工作流程已经大不相同，它依然极具挑战。
Simon Willison @simonw
与编程智能体合作的时间越长，我就越确信，它们让软件工程变得更难了。

借助它们，我们能做出令人惊叹的东西，但要充分释放它们的潜力，需要非同寻常的自律和知识。
💡提出的是工程难度随工具升级而迁移的观点，并无新增实证：自动化释放的能力会被更高的任务复杂度吸收。对 AI 编程产品的启示是，价值衡量应看团队能交付多复杂的系统，而不能只看省下多少编码时间。

我看到有几篇帖子在讨论这件事，所以想解释清楚。如今，每位 Muse 用户都能免费获得一台云端电脑。这是一台真正的电脑，我们精心设计了 Muse Secure VM 的安全架构，让你和你的 Muse 几乎可以完成桌子底下那台电脑能做的一切，同时保护你和系统免受提示注入等威胁。我们在安全博客文章中详细介绍了这些内容：https://t.co/7HmiTrzoTd。你和 Muse 共用的“运行单元”内，活动不受限制，但所有敏感操作都由运行在该单元之外的 Sentinel 监督。同样，所有敏感机密信息——比如你输入 Muse 安全凭据存储中的密码——也都保存在运行单元之外。

运行单元拥有独立的根文件系统（包含完整的 Ubuntu linux 镜像），与你其他更敏感的数据所在的宿主机文件系统分开。由于它与同一台机器上运行的敏感部分相隔离，我们可以，而且确实向用户提供了对运行单元内文件的完整查看和控制权限。就像你在家用电脑上安装 Linux 后一样，你可以四处探索，查看让系统运转的所有文件——既包括 debian 系统文件，也包括实现 Muse 在运行单元内运行的各个部分的二进制文件和数据文件。

这是我们深思熟虑后的选择：你的 Muse Secure VM 确实是你自己的云端电脑。你可以在里面安装软件、编写和编译代码、使用浏览器上网：这是你自己的 Linux 电脑，你可以和 Muse 一起按自己的意愿操作它。在这台电脑里四处探索，并不会让你获得访问 Meta 基础设施或他人数据的任何特权。

容我稍微聊点极客话题……小时候，我喜欢把东西拆开，看看它们是怎么运作的。十几岁时，我开始接触电脑，很快就迷上了 C:\WINDOWS\SYSTEM 和系统注册表，后来又迷上了 Slackware 的 /dev/、/proc/ 等目录。我能看清系统的布局，而随着我探索 DLL 文件和 .so 文件究竟做了什么，我逐渐能够让电脑按自己的意愿工作。

能够以类似的透明程度，将一台真正的电脑交到数百万人手中，我们非常自豪。我们直接在 UI 的 Library 标签页中内置了文件浏览器。我们希望你能看到 Muse 在思考如何更好地为你服务时编写的 markdown 文件，也希望你可以随心探索系统内部。

所以，当你要求 Muse 展示它的整个文件系统，并收到数 GB 的文件时，你看到的就是运行单元的全部内容。它属于你，尽情探索吧！

如果你不像我这样是个极客，或者只是想下载你亲自与 Muse 直接创建的数据，我们也为此添加了一个功能，位置在 Settings > Data controls > Download your agent data。
