快速提醒一下关于用于运行 ARC-AGI-3 的测试框架（harnesses），哪些是可以的，哪些是不可以的：

1. 不可以：为了解决该基准测试而专门定制的框架，或者包含有关基准测试格式/内容知识的框架。

2. 可以：并非为 ARC-AGI-3 开发的通用 API 设置，且对所有 API 用户开放。

过去，我们就如何最好地测试他们的模型与 OpenAI 进行了很多反复沟通，特别是在压缩（compaction）方面。很高兴他们开始找到答案了。

不过你得用对方法才行

以下是我充分利用 Voice 的最佳技巧：

1. 用它来分发任务（delegate），而不是亲自去做具体的活。你给 Voice agent 发出的每个指令，都让它开启一个新的线程（thread），让另一个 agent 来完成工作。Voice 是由较低智力的模型驱动的。通过分发任务，它会把任务交给 5.6 Sol，从而让你的 Voice agent 腾出时间继续陪你工作

2. 经常询问它分发出去的所有工作的最新状态。我发现受委托的 agent 静默失败（silent failure）的概率比预期的要高。通过强制你的 Voice/幕僚长 agent 经常检查受委托的 agent，你可以确保它们都在跟进工作
