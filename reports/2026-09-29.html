大家好，

明天，我们将重新向新订阅者开放 Pro $200 订阅，同时也会调整它的用量计算方式。实际上，算下来，新方案所含用量折合的 API 支出金额将是旧版 Pro $200 方案的一半。

说完这个，让我解释一下为什么会有这一变化，以及为什么你仍然能比一个月前使用 Pro $200 订阅时完成更多工作。

(a) 我们不想在其他方面妥协，并承诺不会重新引入 5h 限制，这样你就能在自己想用的时候充分使用每周额度。
(b) 对于订阅，我们保证，随着时间推移，你始终能完成更多工作，而且质量会越来越高。这意味着，随着模型效率提升，以及我们通过降低 API 价格将这些改进带给你，你花的每一美元都将持续获得更多价值。
(c) 我们不想让自己有动机人为抬高 API 标价，让你看起来获得了很多用量（然后再通过折扣等方式绕过高价）。相反，我们希望继续快速降低 API 上的模型价格，同时提升模型能力。本周，我们推出了 GPT-6 Sol 和 GPT-6 Luna，价格为此前的 50%。长远来看，我们预计价格会降到足够低，让大多数人按需购买用量成为合理选择，而同样花一美元，通过订阅和通过 API 获得的用量将不再有显著差距。
(d) 明天，我们还会为订阅增加一些不消耗用量额度的新内容，具体是什么，我暂时先不透露。

我想在明天所有重磅公告发布之前，把这些情况坦诚地告诉大家。订阅即将迎来许多令人兴奋的新内容，会变得非常有吸引力。不过，我想确保提前告知这项变化，让大家在我们带来一连串好消息之前，就能理解它。

带着 Codex 的问候，
Tibo

有些人看到对齐失效事件，会坚持认为这类似于传统软件中的漏洞。这个类比会实实在在地误导人，因为像打地鼠一样逐个处理对齐失效的案例（就像处理软件漏洞那样），不仅无法解决根本问题，实际上还可能让问题*更糟*：它会让对齐失效更难被发现，甚至可能因处理方式不同，教会机器刻意隐藏对齐失效。传统软件并不是这样运作的。那些坚持说“这就跟修复软件漏洞一样”的人，正自信满满地套用一个丢失了关键信息的类比，带来的困惑比解释更多。
Dean W. Ball @deanwball
我比这更乐观。我认为这主要是一个科学问题，而且我们有可能在这门科学上取得进展。但不，虽然我们今天可以通过一些工程手段来改善 AI 安全性，它从根本上说并不是一个工程问题。
💡核心判断是：逐例修补对齐失效可能降低问题的可见性，甚至诱导隐藏行为，因此可观测违规减少未必代表风险下降。这是机制层面的警示，文中未给实验证据；对产品团队的启示是修复验收需加入跨场景与隐藏行为评测。

很多年前，我纯属偶然地被诊断出患有甲状腺癌，因为申请 US 绿卡需要验血（谢谢你，USCIS！）。当时我才 30 多岁，身体还算健康（至少我自己是这么认为的）。这个消息让我震惊，完全出乎意料。在 NYU Langone 出色的临床团队帮助下，我顺利接受了甲状腺全切除术，随后进行了放射性碘治疗。但那确实是我人生中最充满不确定性、最迷茫的一段时期。

也是在那时，我第一次意识到，没有人能选择置身医疗体系之外。生病不是你想不想、选不选的问题。它会因为各种原因，在某个无法预料的时刻发生在我们每个人身上。正因如此，我们才要共同建设医疗体系，在社会层面相互支持。因为它必须服务每一个人，创建、维护和改善这个体系的复杂程度，使其成为一项极其艰巨的任务，需要各方尽其所能地提供帮助。

今天，我和亲爱的联合创始人 @keunwoochoi、@HenriDwyer、@elmanmansimov、@causalclaudia 以及 Jeff 一起宣布成立 @OrtetAI，为改善我们每个人的健康贡献力量。Ortet 的目标是建立技术基础，让医疗体系能够为每一位患者提供更好、效果更可预期的医疗服务。要实现这一点，必须与整个生态系统中的所有利益相关方密切合作，而 Ortet 与 Thoreau 的紧密合作关系正是促成这一点的部分基础。

Ortet 正迈出漫长旅程的第一步。我坚信，当这段旅程走到终点时，我们能够说，Ortet 为建设更好、更可预期的医疗服务作出了贡献，也因此改善了我们每个人的健康。

考虑到已经有这么多人尝试优化 NanoGPT，我真没想到还能一举缩短 40% 的耗时！
Larry Dial @classiclarryd
@DevenPzak 创造了 NanoGPT 全新历史纪录：39.9s（-27.7s），大幅刷新此前的 67.6s 纪录！

这项纪录为 NanoGPT 引入了一种新的思考范式：与其优化矩阵乘法或加入表达能力更强的运算，不如凭借极其巧妙的工程实现和 ML 判断，逐次优化浮点运算。如果某次浮点运算在某一步价值不高，就跳过它。
具体来说：
-（~8s）采样 softmax。如果某个 token 没有出现在一个批次中，就以一定概率跳过它的 lm_head fwd/bwd。
-稀疏值。只对批次中出现过的 ngram 嵌入执行优化器步骤。将 beta1 设为零来实现这一点。等相应行后续被使用时，再追溯应用 Beta2。
-稀疏更新。ngram 和值嵌入仅每 4 步更新一次，而不是每 2 步一次。
-稀疏通信。将 n-gram 表分片到多个 GPU 上，每一步只传输需要更新的行。
-稀疏优化器状态。对于 n-gram 表，将 Adam 优化器的状态存储从每个参数 2 个浮点数，减少到每 768 个参数 1 个浮点数。
-为 64 维注意力头手工实现 flash attention。

还有几项改动也提升了准确率：
-（~4s）在最后 300 步使用 EMA，同时将 final_lr 从 0.15 提高到 0.3。
-（~1s）新的优化器 Anvil2，通过增加第二个持续跟踪的动量缓冲区来扩展 muon，改进正交化系数，并修改谨慎权重衰减的应用方式。
-在网络中增加几个动态跳跃连接。

这种“浮点运算感知范式”最引人注目的结果是，你可以任意扩大参数规模，唯一限制是可用内存，因为每一步都可以有选择地决定如何在这些参数上花费浮点运算。NanoGPT 一直将活跃参数保持在 124M 以下，但总参数量没有上限，过去一年通过嵌入稀疏化增长到了 640M。这个 PR 在 8xH100 上将这一思路推向极致，扩展到 65B 个稀疏嵌入参数，这部分贡献了该 PR 收益的 25%。在不受 8xH100 限制的前沿规模下，可以想象这一范式能带来怎样的可能性。
